# Sample Tracker

Group: Tracking · File: `sample_tracker.tsx`

> See [`docs/CROSS_CUTTING.md`](../../../docs/CROSS_CUTTING.md) for rules shared across interfaces (Cobalt boundary, dark mode, sandboxing, etc.).

## Business Objective

Track physical sample gowns across locations/status (studio, trunk shows, production, etc.), their condition, and timely alerts when samples are off-site or need attention — so samples aren't lost, damaged, or unavailable for a bride's appointment.

## Workflow

1. Samples are logged/added or retired via Add/Retire tracking, with condition status recorded.
2. **Close-size matching (Sample Alerts panel, rebuilt 2026-08-14):** for each of a client's favorite styles, matches Active Sample Log records via the `parent_style` record link (not name text) — exact match (same size) always shown, close-size alternatives (±1 on the `SIZE_ORDER` axis) shown alongside/instead, otherwise a "no stock" state; ties broken by preferring `In Studio` over `Away`/`Trunk Show`. See Rules below for the full mechanism — this restores/supersedes the "deliberately removed" size-distance display noted in the original build, and the "Sprint 7 — Alternate-Size Match Fix" follow-up story below is now implemented, not just planned.
3. Alert automation watches location/status category and fires Slack alerts based on a sequencing threshold — this is the first work item to confirm for `JuliMigLui37116`, not yet finalized.
4. **Add Sample** — a "+ Add Sample" button (visible when the interface has write permission on Sample Log) opens a modal requiring a linked `parent_style` (record picker over the DF Styles table — searchable, matches on `style_name`), Size, and Type; Location, Notes, and photo are not part of creation (see Condition/Photo below). Required-field errors are shown inline; the Save button disables while the write is in flight to prevent duplicate submissions. New samples are created with `status = Active`.
5. **Retire / status change** — there is no separate Retire button or confirm flow. The sample detail modal's `status` field is a plain dropdown (`StatusFilledSelect`) offering all of that field's live choices (including Active and Retired); picking "Retired" there is the only way to retire a sample. The default table filter is `status = Active`, so retired samples drop out of the main view but remain queryable/visible when that filter is cleared or when reopening the record directly.
6. **Parent Style (in the detail modal)** — the sample detail modal has a "Parent Style" field: the same DF Styles record picker used in Add Sample (`RecordSelect`, module-scoped so both modals share it), initialized from the record's current `parent_style` link. The legacy free-text Style Name field is no longer shown or editable anywhere in this interface — `style_name_legacy` stays a real, writable Airtable field, just not surfaced in the UI. (`getEffectiveStyleName()` still reads it as a fallback for display/search/sort/alert-matching on older records; that logic is unchanged.)
7. **Condition + Photo** — recorded via a native Airtable Form (an Interface Form page, not a classic Grid-view form), not in-app: the code cannot reliably persist file uploads through the Blocks/Interface Extension SDK, so condition changes and photo evidence are captured entirely outside this file. The sample detail modal has a "Register Condition" button that opens that Form in a new tab with the `sample` field prefilled and hidden (`?prefill_sample=<recordId>&hide_sample=true`). Below it, a read-only "Condition History" table (columns: Date, Condition, Notes, Attachment; sourced from `sample_condition_history`, filtered to that sample, sorted by `logged_at` descending) replaces the earlier badge/timeline layout — every row, including the most recent, renders the same four columns (the most-recent row just gets a subtle highlight). Clicking an Attachment thumbnail opens an in-app `ImageLightbox` (pan-to-zoom drag/double-click/Ctrl+wheel via `ZoomableImage`, download, cycle through multiple photos on the same row) instead of a new browser tab. There is no in-app edit path for condition/photo by design, and the lightbox has **no delete action at all** — Condition History is an append-only audit log, so removing a photo from it isn't offered in this UI (client confirmed 2026-08-12: "quítalo, que no se pueda borrar").

## Rules

- Damaged, Archived, and Other are explicitly **excluded** from alerting.
- Dark mode in this file uses a bespoke "champagne" `LIGHT`/`DARK` token object applied via inline `style={}` — evaluated against `fulfillment.tsx`'s pattern during the Pipeline dark-mode unification work and **not** selected as canonical, but this file was left as-is (out of scope for that work). Not yet decided whether Sample Tracker should eventually migrate to the canonical Tailwind `dark:` pattern.
- A separate "Sample Tracker — Future Enhancements" story (repair priority flagging, PR pool tracking) is distinct from and NOT covered by the Close-size Availability story.
- Original combined 4-feature story scored 57/100 on DoR Auditor (scope too broad + no UI designs) — this is why it was split into three stories; keep them separate going forward rather than re-merging.
- ~~Planned follow-up (Sprint 7, "Sample Tracker — Alternate-Size Match Fix")~~ — **done, 2026-08-14.** Close-size matching (exact/close/no-stock, ±1 threshold, in-studio tiebreak) is implemented — see the "Parent-Style Link Constraint + Close-Size Matching" entry below. Julia confirmed this story is authorized.
- Never include `import './style.css';` in this file.
- **Style name resolution (DFS-4, 2026-08-12):** Sample Log's `style_name` field was renamed to `style_name_legacy` and is now fallback-only. New samples link to a DF Styles record via `parent_style`, and `parent_style_name` (a lookup) reflects that linked record's `style_name` live. The formula field `label` (now Sample Log's primary field) prefers `parent_style_name`, falling back to `style_name_legacy`. Anywhere in code that displays/matches/sorts a sample's style name must go through `getEffectiveStyleName(record)`, not read `style_name_legacy` directly — that field is blank on every sample created after this change, and reading it directly silently drops those samples from search, sort, table display, and the close-size/alert-matching logic.
- **Style Name Legacy is no longer editable in this UI (client feedback, 2026-08-12):** `SampleDetailModal`'s old free-text Style Name row (bound to `style_name_legacy`) was replaced with a "Parent Style" record picker over `parent_style` (link → DF Styles), reusing the same module-scoped `RecordSelect` component `AddSampleModal` uses. `style_name_legacy` remains a real, queryable Airtable field — it's just not read or written anywhere in this modal's own editable-field logic anymore. `getEffectiveStyleName()` is unaffected and keeps reading it as a fallback.
- **`sample_condition_history` table** (`tblCeawyDvoWBj2hQ`) is the system of record for condition + photo, one row per check: `sample` (link → Sample Log), `condition` (Good Condition / Damaged / Needing Repair), `photo`, `notes`, `logged_at` (formula `CREATED_TIME()`, used for sorting). Sample Log also has `current_condition_rollup`, a rollup of linked `condition` values — this is Airtable-grid-only, **not** authoritative (rollup order isn't guaranteed chronological); the interface always computes "current condition" itself from `sample_condition_history` sorted by `logged_at`.
- **Condition Form URL is never hardcoded.** It's resolved live from the `resources` table (`tblFa56lQwVacMXto`) by matching `record.name === 'sample_condition_entry_form'` and reading its `url` field — same pattern `recap.tsx` uses for `attachments_form_url`, because sandbox and production are separate bases with independently-editable resource records holding different URLs for the same logical resource. If that resource record can't be found or its URL is blank, the "Register Condition" button disables itself with a "Condition form link not configured yet." note rather than opening a broken link. The prefill query param's field name (`sample`) is also read live off the field itself (`getFieldIfExists(...).name`), not hardcoded, so a future rename of that field doesn't silently break the link.
- Confirmed working end-to-end in Sandbox 2026-08-12: Register Condition opens the Form with `sample` prefilled/hidden, and a submitted entry appears in the sample's Condition History on return to the interface.
- **Retire button removed (client feedback, 2026-08-12):** the modal's two-step "Retire" / "Confirm Retire?" button, its `retireStep`/`retiring`/`retireError` state, and the optimistic-update/rollback logic behind it were removed entirely — per the client, changing `status` to "Retired" via the existing `StatusFilledSelect` dropdown (unchanged) is sufficient on its own. That dropdown/`handleStatus` remain the sole path for changing status, including to Retired.
- **Condition History is now a strict 4-column table** (Date / Condition / Notes / Attachment), not a card+timeline layout — every row (including the most recent) uses the same columns; the most-recent row is only visually distinguished by a subtle background highlight, not a separate treatment.
- **`ImageLightbox`** (component, built on a `ZoomableImage` sub-component matching the client's reference pattern) is a full-screen in-app preview for Condition History attachment thumbnails: pan-to-zoom via drag, double-click (1x↔2.5x), or Ctrl/Cmd+scroll wheel (1x–6x, with a live percentage readout and zoom in/out/reset controls), plus a real Download link and prev/next cycling with a position indicator when a row has more than one photo. **There is no Delete action** — Condition History is an append-only audit log, and removing a photo from it is a product decision the client explicitly deferred, so no delete affordance is offered in this UI (client confirmed 2026-08-12: "quítalo, que no se pueda borrar").

### Parent-Style Link Constraint + Close-Size Matching (2026-08-14)

Full session transcript: [`2026-08-14_sample-tracker-close-size-matching-session-transcript.md`](../../../session_summaries/2026-08-14_sample-tracker-close-size-matching-session-transcript.md).

- **`is_parent_style`** — new checkbox field on DF Styles (`fldahgBBH19TcIPzi`, both sandbox `appMmEE4zyHMGhkkd` and production `appUC2NFAlURayLx9` — identical field ID on both bases). Manually maintained by staff; marks which DF Styles records are true parent styles rather than variants (populated via a one-time backfill matching on `"customized"` in the style name — see `danielle-frankel-studios/backfills/`). Both `AddSampleModal` and `SampleDetailModal`'s style pickers now filter to `is_parent_style === true` (the detail modal keeps a sample's *currently linked* style visible even if not a parent, so existing links never render blank).
- **`champion_samples`** — new `multipleRecordLinks → Sample Log` field on DF Clients (`fldEDcL6wGGmUt6ni`, same ID both bases). Written by the `Sample Tracker | Champion Match on Style Change` automation (script: `danielle-frankel-studios/automations/danielle_frankel_studios/champion_sample_match.js`) whenever `favorite_styles_from_acuity` changes — computes, per favorite style, the best in-stock sample by the same SIZE_ORDER/threshold/tiebreak logic as the interface. The automation's trigger is scoped to a view (`sample_match_trigger`: DF Clients where `favorite_styles_from_acuity` and `ready_to_wear_size` are both non-empty) rather than firing on every update.
- **`ready_to_wear_size`** — DF Clients' original `ready_to_wear_size` field (`fldEEH4CK3Qqp0g0C`) was renamed to `ready_to_wear_size_manual`; a new **formula** field named `ready_to_wear_size` (`fldSwfR25uvynWKI5`, same ID both bases) is now the source of truth for RTW-size matching everywhere — `IF({ready_to_wear_size_manual} = BLANK(), {Size from Acuity Intake}, {ready_to_wear_size_manual})`, since manual entry is rarely filled by staff but Acuity intake almost always is. Code must read this formula field, never `ready_to_wear_size_manual` directly.
- **Close-size matching (Sample Alerts panel)** now matches via the `parent_style` record link (`fldFWWLHDvxG0gtkH`), not name-text substring matching — a sample with no `parent_style` link is never a valid candidate. `SIZE_ORDER` maps size strings (US numeric, letter, OS, EU 35–42 as its own axis) to a numeric position; `CLOSE_SIZE_THRESHOLD = 1`. Per favorite style: exact match (distance 0) always renders, even alongside close alternatives (distance ≤1) — never hidden by them; close alternatives never imply the exact requested size is in stock; no candidates within the threshold renders a "No stock" state; ties at the same distance prefer `In Studio` over `Away`/`Trunk Show`. A client's favorite styles are now read from the client's own `favorite_styles_from_acuity` link field (real DF Styles record links) rather than the appointment's text lookup, so matching is by record ID, not name substring.
- **`parent_style` backfill state:** many older Sample Log records had this link empty (populated by name-matching legacy `style_name_legacy` text against DF Styles, exact + fuzzy-prefix). Sandbox is fully backfilled (922 of 1,348 previously-empty records linked; 426 left unresolved — no clean text match, need manual linking). Production is **only** backfilled for a 29-style/185-sample scoped test (see the transcript) — the rest of Production's Sample Log is explicitly deferred post-close by the client. Any code/report relying on `parent_style` coverage in Production should account for this gap until the full backfill runs.
- All backfills for this story are logged in `danielle-frankel-studios/backfills/` (one `.md` summary + `.csv`/`.xlsx` audit trail per run) — check there before assuming current data coverage.
